# 步步整合報價與綠界刷卡

目前：介接程式已建立，正式收款未啟用。尚未申請綠界商店，網站保持既有私人存取設定。這兩項都會阻止外部客戶付款／綠界通知；不可僅打開付款按鈕就視為可上線。

## 報價流程

管理員登入 → 名單「建立／查看報價」帶入客戶及包材 → 新增搬運、打包、寄倉或其他品項 → 儲存草稿 → 開立鎖定 → 私人報價連結 → 客戶確認 → 綠界信用卡一次付清。

全額新台幣付款。各行單價為該報價應計金額，總額包含管理員列出的所有費用與稅額，不於刷卡時加收。沒有自動發票、分期、訂金分拆、退款或自動對帳查詢功能。發票依公司既有流程另行開立。包材選購不保留庫存；供貨、配送與服務日期由管理員確認。

已開立報價不可變更；尚無交易可作廢。每張報價只有一筆金流交易，避免重複建立扣款。付款失敗、超時或離開付款頁時，管理員先至綠界查核，不要逕行開新單再次扣款。退款須由綠界商店後台操作並人工追蹤；本站付款狀態目前不自動同步退款。

## 啟用環境設定（僅伺服器）

在 Sites 環境設定安全輸入，不要貼入聊天、前端或 Git：

- `ECPAY_MERCHANT_ID`、`ECPAY_HASH_KEY`、`ECPAY_HASH_IV`：綠界核發的商店資料。
- `ECPAY_MODE=test` 或 `live`：測試與正式環境須分開，既有交易不能中途切換商店／金鑰。
- `PAYMENT_PUBLIC_ORIGIN`：經確認的 HTTPS 官網來源，例如 https://example.com，不含路徑或結尾斜線。
- `ECPAY_CALLBACK_READY=true`：確認 `POST /api/payments/ecpay` 從外網不需登入，且可收到綠界通知後才能設定。
- `ECPAY_ENABLED=true`：上述設定完成並完成下列驗收後啟用。

目前 Site 為私人網站，通知會被平台存取控制擋住。正式上線須由擁有者決定公開網站／可接收通知的部署安排；管理員 API 仍以授權信箱限制。報價使用不可猜測的隨機連結，持有連結者可讀取及確認，請只傳给對應客戶。前端與 API 不儲存信用卡資料。

## 上線驗收

1. 用綠界官方測試帳號設定測試環境，完成實際測試卡付款及伺服器通知。
2. 核對報價總額、名單品項、客戶确认、付款成功／失敗、重新整理與重複通知。
3. 確認錯誤簽章／金額／商店通知被拒絕，模擬付款不記實收，測試成功只記測試。
4. 使用正式商店資料，完成公司授權的小額付款及退款核對；此步尚未執行。
5. 檢查綠界通知可達與商店交易紀錄；瀏覽器返回不代表付款成功，僅驗證過的伺服器通知會更新付款。
